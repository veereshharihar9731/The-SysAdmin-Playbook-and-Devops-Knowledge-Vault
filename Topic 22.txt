Tags, Reflog & Meaningful Commit Messages

1. Git tags — Mark a specific version
A Git tag gives a name to a particular commit. Think of it as putting a version label on a tested, stable release of your project.

git reflog — Recover from Git mistakes
git reflog records where your local Git references, such as HEAD, have pointed recently. It is especially helpful if you accidentally reset a branch, switch branches, or lose track of a commit.

Important points:
- Reflog is local to your repository; it is not a replacement for a remote backup.
- Recovery is not guaranteed forever. Reflog entries and unreachable commits can eventually expire or be cleaned up.
- git reflog doesn't undo mistakes automatically; it helps you find the commit or branch position you need.
- Avoid running another reset --hard while trying to recover until you've identified the correct commit.

3. Writing meaningful commit messages
A commit message explains what changed and why. Good messages make it easier for teammates, reviewers, and support engineers to understand project history during troubleshooting.
